# 信号分析法 · 拿到赛题的第一件事

> **这是整个流程的第一步，排在选型之前。**
> 小陈 2026-09-18 立的规矩：每场比赛，先读信号，再谈方向。
>
> 一个比喻：赛题是主办方写给你的**情书**，但真话从来不写在正文里。
> 正文说"欢迎自由创作"，**落款、附言、随信寄来的礼物**才告诉你他到底想要什么。
> 信号分析就是读落款和附言。

---

## 为什么它排第一

一场比赛的成败，七成在开工之前就定了。

主办方掏钱办赛，一定有他想要的东西——想招人、想推产品、想要曝光、想找项目、想完成 KPI。
**这个"想要"不会写在赛题里，但它决定了评委手里的尺子。**

读不出信号，你就是在猜；读出来了，你是在答题。

## 七个信号源（按可信度排序）

### ① 评分权重表 —— 最硬的信号
权重最高的那一维，就是主办方真正在买的东西。
> 天猫：AI 应用能力 25%（五维最高）→ 这不是一场"做个好产品"的比赛，是一场"证明 AI 不可替代"的比赛。

### ② 谁在办 + 谁是合作伙伴
| 主办方类型 | 他想看到什么 |
|---|---|
| 云厂商（阿里云、腾讯云、华为云） | **用量** —— 你用了多少他家的服务 |
| 芯片厂（Intel、英伟达、高通） | **端侧 / 本地推理 / 软硬协同** |
| 模型平台（讯飞、百度、商汤） | **生态** —— 你在他的框架里长出了什么 |
| 电商 / 消费品牌 | **传播** —— 能不能被拍成视频、被转发 |
| 高校 / 政府 | **落地** —— 能不能真的用起来、有没有社会价值 |
| 公益机构 | **社会价值叙事** |
| 投资 / 孵化机构 | **商业模式和团队** |

### ③ 嘉宾阵容 —— 最容易被忽略、但极准
**请谁站台，就想要谁那一类的东西。**
> 天猫请了脱口秀演员 + 视频制作 UP 主 + 生活类 UP 主 当召集人/推荐官/观察员。
> 一场技术比赛请三个做内容的人 → **要的是能被拍成视频、能传播的作品。**
> 叠加人气投票占 20%，"好不好看、好不好讲"直接值 20 分。

### ④ 奖励结构 —— 发什么，就想推什么
- 发某家的 token / 算力券 → 希望你用他家模型
- 发**面试绿通 / 实习机会** → 这场比赛本质是**招聘漏斗**，主办方在看人不只看项目
- 发硬件设备 → 硬件方是金主，方案沾硬件会加分
- 发"政企资源对接 / 孵化" → 想找能落地的项目，要讲清商业路径

### ⑤ "额外加分"四个字出现的地方
这几乎总是**赞助商掏钱买的方向**，且通常写得很轻，容易被跳过。
> 天猫官网："软硬协同、端云结合方案额外加分" ← Intel 是首席战略合作伙伴。
> 这种加分是**白送的**，不吃亏。

### ⑥ 赛道命名里的动词和否定句
赛道名是压缩过的需求，尤其注意**否定句**——那是主办方在排除他不想看到的东西。
> "让 AI 真正进入每一天，**而不只在聊天框**" → 明确反对纯 ChatBot。
> "用 AI 让原本困难的事，**第一次**变得不困难" → 要的是"以前做不到"，不是"以前能做但更快了"。

### ⑦ 特别赛题 vs 自由创作
- **特别赛题** = 赞助商指定的方向，**竞争通常更少**（命题门槛劝退了一批人），但题目框死、发挥空间小
- **自由创作** = 人多，但能打自己的牌
- 有些特别赛题挂着额外身份（如"入围国创赛题"），要单独算战略价值

## 信号读完，先定一件事：这场比赛我图什么

**这是小陈提的关键补充：不是每场比赛都要拿奖。**

参赛目的分四档，**开赛前就定**，不要打到一半才发现自己其实在玩：

| 档 | 目的 | 投入 | 成功的定义 |
|---|---|---|---|
| **A · 冲奖** | 要名次、要奖金、要背书 | 全力，排满工期 | 进决赛 / 拿奖 |
| **B · 攒资产** | 做一个能用第二次的东西 | 中高，但严守功能边界 | 产出可复用资产，名次次要 |
| **C · 认人 / 探路** | 认识主办方、评委、其他队；摸未来方向 | 作品够用即可，**精力花在现场社交** | 加到对的人、看懂一个新领域 |
| **D · 玩一玩 / 体验** | 练手、体验新赛制、陪朋友 | **限时**，不许超 | 玩完了，没拖累主线 |

### 怎么判断该打哪一档

| 信号 | 指向 |
|---|---|
| 奖池大 + 评分透明 + 赛道对口 + 复用率高 | **A 冲奖** |
| 命题正好能沉淀进主 IP（青少年 AI 教育 / 数字员工） | **B 攒资产** |
| 奖池一般，但主办方 / 评委 / 参赛者是想认识的人 | **C 认人** |
| 赛制新奇但跟主线无关 | **D 玩一玩**，且必须限时 |

### ⚠️ 队内目的对齐（最容易翻车的地方）

**同一场比赛，队友的目的可能和你不一样。**

- 小陈的默认目的：全链路体验 + 主 IP 复利 + 攒可复用资产
- 队友的目的可能是：借平台认识更多人和机构、探索未来方向（≈ C 档）

一个想冲奖、一个想社交，会互相拖：冲奖的人怪队友不写代码，社交的人怪队友不出去聊。

> **开赛前问一句："这场你想要什么？"** 一句话的事，能省掉一场内耗。
> 答案不一致不是问题——**说清楚就能分工**：一个守作品，一个跑关系，两头都收。

## 输出格式

信号分析的结论写进比赛记录的**第一节**，不要藏在附录里。至少包含：

```
## 信号（主办方到底想要什么）

1. 【评分权重】最高的一维是 ___ (__%)，说明这场比赛真正在买 ___
2. 【主办与伙伴】___ 办的，___ 是金主 → 想看到 ___
3. 【嘉宾阵容】请了 ___ → 说明要 ___
4. 【奖励结构】发 ___ → 本质是 ___
5. 【白送的加分】___
6. 【明确的否定】主办方不想看到 ___

**一句话翻译**：这场比赛真正在找的是"____"的作品。

**我这场图什么**：A 冲奖 / B 攒资产 / C 认人探路 / D 玩一玩
**队内目的是否已对齐**：☐
```

## 这份文档怎么长大

每打完一场，回来补：
- **猜错的信号** —— 哪条读反了？为什么？（这是最贵的经验）
- **新的信号源** —— 有没有第八条？
- **新的主办方类型** —— 补进第②节的表格
