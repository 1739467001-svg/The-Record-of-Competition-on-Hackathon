### 三个反复出现的工程习惯（这是护城河，不是巧合）

1. **零依赖 / 零构建的纯静态版本。** 多个项目明确写着"双击 index.html 即可运行""Three.js 已打包进 vendor/，完全离线可用"。
   → **比赛现场断网、评委电脑没 node、U 盘拷过去就要演 —— 这个习惯能救命。**
2. **一键部署链路熟。** Vercel / GitHub Pages / Zeabur / 阿里云轻量 / Docker + Nginx 全都跑通过。
   → 队里"补部署上线这一环"的人就是他。
3. **文档先行。** 几乎每个项目都有 PRD、README、架构图、汇报材料。
   → 路演材料对他是副产品，不是额外负担。

## 五、诚实的短板（选型时要绕开）

| 短板 | 证据 | 结论 |
|---|---|---|
| **深度算法 / 模型训练** | `machine-learning` `AlphaFold1` 都是知识整理，不是训练代码 | **不接需要刷榜、训模型、拼精度的赛道** |

| **移动原生 App** | 130 个仓库里没有 iOS / Android 原生项目 | 需要上架 App 的赛题，改用 Web / PWA 应对或不接 |
| **高并发重后端** | 有 NestJS 全栈系统，但不是主场 | 三天做不完的重后端架构，砍功能而不是硬扛 |
| **收口能力** | 大量 Demo，少有转化成持续产品 | **每场比赛必问：这东西还能用第二次吗？** |

## 七、回写规则

每打完一场比赛：
1. 新做出来的、**能换皮复用**的东西 → 加进对应军火库表格
2. 踩到的新短板 → 加进第五节
3. 新增的技术栈 → 更新第二节

**只加真正可复用的。** 一次性的临时代码不进弹药库 —— 信号优于堆积。
