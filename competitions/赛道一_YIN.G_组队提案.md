## 三、创作方向

### 3.1 项目名称

**开图 Unfold**

### 3.2 一句话定位

> **我们做了一个让任意一个物理场地在 30 分钟内「上线」的工具，给所有想让自己的场地能被一句话调度的机构——高校、度假村、园区、医院、商场，解决空间服务「能力早就有了，却装不进新地方」的问题。**

### 3.3 赛道一 · 核心说明

**解决了什么产品痛点？**

面向任何希望自己的场地"能被一句话调度"的机构：高校、度假村、园区、医院、商场。这类空间服务的**能力早已不稀缺**——找路、找房间、预约、问答、看态势，技术上全都成立，我们自己也已经在一所高校校园上线跑通。真正的瓶颈在入口：**每接入一个新场地，都要先测绘、建模、录数据，几万块、几星期起**，于是这套能力永远只能落在一两个样板项目上，走不出去。所以我们要解决的不是"做得好不好"，是"**进不进得来**"——把一个新场地的接入成本，从一个需要立项的工程，压缩成一个人半小时的散步。

**产品核心功能（3点）：**

1. **走一圈就开图。** 一人手持全景相机沿场地主路步行或骑行一圈，约 30 分钟连续录制。每一帧都是 360°，天然覆盖道路两侧全部空间，无需逐点取景、无需多次往返——这是全景相机相对手机与单反不可替代的采集效率，**也是接入成本能被压到一次散步的根本原因**。
2. **AI 把现场翻译成可被调度的空间。** 从全景流中识别建筑与出入口、数楼层反推真实高度、提取立面纹理、生成可通行路网。输出的不是一段视频，是**一份机器能读的场地结构**——这一步是"能被问、能被找、能被预约"的前提。
3. **同一套服务引擎即刻接管。** 场地一旦开图，找路、找房间、预约、路线规划、场景问答立刻可用。我们已在一所高校校园上线验证，本次在度假村营地现场再跑一遍：**同一句话，两个世界。**

**AI技术运用方向：**

以阿里千问多模态大模型为核心，对全景切片做建筑与出入口识别、楼层计数、立面材质判别、可通行区域判定；配合单目深度估计完成球面反投影与空间对齐，输出结构化场地数据。AI 在本产品中承担的是**「把画面翻译成结构」**——它的产物不是给人看的图，是给系统用的数据。

**目标效果：**

让任何一个物理场地，在三十分钟之内，从"一个只能靠人问路的地方"，变成"一个能被一句话调度的地方"。

**商业化路径（这是我们做这件事的目的）：**

| 层 | 说明 |
|-|-|
| **接入即收费** | 每开通一个新场地收一次接入费，直接对标现有「测绘 + 建模」的既有报价——我们卖的是同一件事的几分之一成本。 |
| **平台订阅** | 场地开图之后，按年订阅其上的服务能力（导航 / 预约 / 问答 / 态势）。**这是持续收入，也是本产品从"服务公司"变成"平台"的地方。** |
| **复制成本趋零** | 接入成本被压到一次散步之后，场景可以横向复制：学校、度假村、园区、医院、商场、政务大厅——**同一套引擎，换一个场地**。这是本项目真正的想象空间所在。 |
| **场地会变，所以要重走** | 改造、扩建、换季布展都会让场地失效，重新开图仍然只要 30 分钟——续费的理由是内生的，不需要销售去创造。 |
| **对影石的价值** | **每开一个新场地要走一圈，场地变了还得再走一圈。** 相机不再是拍一次就完事的器材，而是**每一个新场地的入场券**——这是一条随场地数量线性增长的 B 端出货线。 |

## 四、所需资源

### 4.1 设备需求

| 设备类型 | 需求数量 | 用途说明 |
|-|-|-|
| **全景相机（X5）** | **2 台** | **核心采集设备。** 1 台用于巡场连续录制，1 台作固定机位对照与热备。**必要性：** 本方案全部输入来自连续全景流，单机在长时间录制中若过热、掉电或存储写满，当天采集即作废且无法重来，备机是交付的保险。 |
| 运动相机（Ace Pro 2） | 1 台 | 补拍建筑立面细节、出入口与低角度近景，作为全景纹理在高层／遮挡区域的高清补充。 |
| 云台相机（Luna） | 1 台 | 拍摄 30 秒产品演示视频，并记录团队真实创作过程（Bold Trace 素材）。 |

### 4.2 场地与场景需求

| 场景 | 使用时间/外出时间 | 必要性说明 |

### 4.3 技术支持需求

| 需求类型 | 具体说明 | 紧急程度 |
|-|-|-|
| **技术指导（影石工程师）** | **三个问题，直接决定技术路线：**<br>① SDK 能否导出 equirectangular（等距柱状投影）原始全景？分辨率与格式如何？<br>② 相机是否输出 GPS / IMU 姿态轨迹？——**这一条决定路网生成与空间对齐能否自动化**<br>③ 连续长时间录制的续航与存储上限是多少？——直接决定单次开图能覆盖多大场地 | **高** |
| AI模型/API支持 | 阿里千问多模态大模型 API（建筑与出入口识别、楼层计数、可通行区域判定）；Luxreal 3D 生成的 API 接口与调用配额。 | **高** |
| 云服务/算力 | 全景视频抽帧后的批量多模态推理算力（单次开图约产生数百帧待推理切片）。 | 中 |
| 用户访谈对接 | 3 人次摄影博主访谈，**希望优先安排有商业空间全景拍摄经验者**（楼盘 / 园区 / 校园 720 全景方向）——他们是这条业务链上真实的服务提供方，其报价方式与交付痛点直接决定我们的接入定价模型。 | **高** |

### 4.4 其他需求

- **路演现场：** 需外接屏幕或投影一路、稳定电源一路。我们的 Demo 为**纯前端静态包，断网可完整演示**，不依赖现场网络，可作为组委会的低风险展位。
- **合作方对接：** 若组委会有园区运营、文旅度假、商业地产或高校后勤方向的合作单位，我们希望在 Demo Day 期间做一次面向真实付费方的接入需求与定价验证。

**目前最大的挑战/不确定性：**

最大的不确定性是**影石相机能否输出 GPS / IMU 姿态轨迹**——有，则路网生成与空间对齐可自动完成，"走一圈就开图"是字面意义上的全自动；没有，则需退回手动锚点方案，工作量增加约五成、也直接影响我们对单场地接入成本的测算，因此希望能在 9/22 当天尽早得到工程师的明确答复。
