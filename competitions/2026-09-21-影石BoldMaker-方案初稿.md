# 《众目 Many Eyes》· 方案初稿 v0.1

> 队伍：**YIN.G** ｜ 赛道一：AI+影像产品开发 ｜ 2026-09-22 Hack Day 1
> 基于许恒 9/22 车上口述方案（景区 3D 粒子照片墙）改造。**改了什么、为什么改，第二节讲清。**
> 产品名待定，《众目》只是提议 —— 取"很多人的眼睛，拼出一个地方"。

---

## 一、一句话定位

> **一个人拿 360 相机在燕子矶环拍一圈，这座地标就多长出一片粒子。
> 一百个人拍过之后，它在数字世界里被拼完整了。**
>
> 《众目》不是照片墙，是**一座由众人的眼睛共同长出来的数字地标** ——
> 而现有的打卡和相册，只能把照片叠成一堆，拼不出一个地方。

## 二、对许恒原案的保留与改造（诚实版）

### ✅ 完整保留的部分（这是方案的灵魂，不动）

| 原案要素 | 保留理由 |
|---|---|
| **3D 粒子构成的地标** | 视觉冲击是路演最快见效的一项，且是我们的主场（11 个 3D 场景工程） |
| **打卡补齐 · 上传即贡献** | **个人行为 → 集体作品**，这个叙事很动人，是整个方案最值钱的一句话 |
| **手势张开 / 收缩切换视图** | 命中参考方向③"智能交互（无接触）"，且摊位路演能让评委自己上手 |
| **每个景区独立模型与地图** | 可扩展性叙事，吃"市场潜力与应用前景 10 分" |
| **可以用别人上传的内容** | 社区感，弱化冷启动 |
| **iPad 当画框做演示** | 现成、稳、不依赖硬件到位 |

### 🔴 必须改造的两处（不改会直接丢 20 分）

#### 漏洞一：影石设备在原案里是可有可无的

拿赛道一的筛子过一遍 —— **"换成一台普通手机能不能做？"**

原案里：用户打卡上传的是**普通照片**，粒子墙不需要 360°，
360 素材只被当成"地球仪般的环绕背景感"用了一下。

**那是装饰，不是地基。** 评委（席上坐着影石的人）第一句就会问：
> "这跟我们的相机有什么关系？换成手机拍不也一样？"

→ **「影石设备/SDK 使用深度与效果 10 分」直接丢掉。**

**改造：把"粒子从哪来"换掉。**

| | 原案 | 改造后 |
|---|---|---|
| 一个粒子 = | 一张照片（平面贴图） | **一次 360° 环拍采样出的一片三维点** |
| 手机能做吗 | ✅ 能 | ❌ **不能** |

**原理**：普通照片是一个平面截面，一百张也拼不出可靠的三维。
而 360 相机在一个点环拍，拿到的是那个位置的**完整球面采样** —— 有了球面信息，
单点就能反投影出一片带真实颜色的三维粒子；多个点位叠加，地标的轮廓就长出来了。

> **一句话给评委**：
> **"手机拍的是一张照片，360 相机拍的是一个位置。照片堆不出地方，位置可以。"**

#### 漏洞二：AI 在哪？

通读原案：粒子渲染是图形学，上传是 CRUD，手势识别是现成库，照片检索是数据库查询。
**「AI 技术在产品中的实际作用与成效 10 分」目前是空的。**

判据还是那条：**把 AI 拿掉，产品还在吗？** 原案里 —— 还在。那就是浅。

**改造：让 AI 承担三件拿掉就不成立的事。**

| # | AI 动作 | 拿掉会怎样 | 对应参考方向 |
|---|---|---|---|
| ① | **深度反投影**：从全景图估计每个方向的深度，把球面像素变成三维粒子 | 没有粒子，只剩一张贴图 | 全景智能重构 |
| ② | **空间配准**：判断新上传的这一圈是在哪个位置、朝哪个方向拍的，自动并入已有点云 | 每个人的粒子各自飘着，拼不成一个地标 | 全景智能重构 |
| ③ | **语义标注与讲解**：千问多模态识别这片粒子是地标的哪一部分（城墙/江面/石阶），生成讲解 | 点开一个粒子只有一张图，没有信息 | AI 影像处理 |

拿掉 AI → 剩一个照片上传站。**深度立住了。**

### ⚠️ 必须换掉的场景：南京大屠杀纪念馆

原案以"南京大屠杀墓碑"为参考场景。**我建议换掉，这不是保守，是真实风险。**

那是国家公祭场所。把遇难者做成"粒子"、配上"打卡""补齐""商业化"的游戏化机制 ——
评委席上坐着**政府和媒体**，这个组合极易被读成不敬。一旦被这么读，技术再好也救不回来。

**替代场景（按推荐度）**：

| 场景 | 为什么 |
|---|---|
| ⭐ **栖霞山 / 栖霞寺** | **比赛就在栖霞区，政府是指导单位** —— 送到嘴边的主场分 |
| **明城墙 · 台城段** | 体量大、轮廓清晰，粒子长出来最好看 |
| **长江大桥** | 结构感强，工业美学，视觉冲击最高 |
| 燕子矶 | 团队已实地去过有素材 —— **但它也是丛葬地之一，做游戏化机制同样要谨慎**，建议只作为素材来源，不作为主叙事场景 |

> **纪念叙事不是不能做，是不能用"打卡补齐"的游戏机制做。**
> 真想保留厚重感，可以把栖霞山/明城墙的"历史层"作为 AI 讲解的内容，
> 而不是把纪念场所本身变成收集玩法。

## 三、核心机制（改造后）

### 用户动线

```
1. 到一个地标 → 打开 App / 网页，看到这个地标当前的粒子云
   （稀疏 = 很少人拍过；稠密 = 很多人拍过）

2. 用影石相机原地环拍一圈 → 上传

3. AI 三步：
   深度反投影 → 生成一片三维粒子
   空间配准   → 并入这个地标的公共点云
   语义标注   → 标出这片粒子是地标的哪一部分

4. 眼看着地标"长"稠密了一点 —— 你的那片粒子带着你拍的真实颜色

5. 手势张开 → 粒子散开成照片墙，看见每个人的原始全景
   手势收缩 → 回到地标全貌
   点任一粒子 → AI 讲解这里是什么、谁拍的、什么时候
```

### 一句话机制（路演开场用）

> **"以前你去一个地方，带走一张照片。
> 现在你去一个地方，给它留下一片。"**

## 六、技术路线（含降级，44 小时能落地的版本）

### 🔴 先说实话：真三维重建做不完

从多视角全景做 SfM/MVS（OpenMVG/COLMAP）44 小时内跑通 + 调参 + 出效果，**风险极高**。
**不要走这条路。**

### ✅ v1 实际路线：单目深度 + 球面反投影 + 粗配准

```
全景图（等距柱状投影 equirectangular）
   ↓  单目深度估计模型（Depth Anything 类）
每个像素的深度
   ↓  球面反投影：(经度, 纬度, 深度) → (x, y, z)
一片带真实颜色的三维粒子（一个机位 = 一个"粒子球"）
   ↓  粗配准：GPS / 手动标注锚点
并入这个地标的公共点云
   ↓  Three.js / R3F Points 渲染 + 手势控制
可交互的粒子地标
```

**为什么这条路能成**：
- 单目深度估计几小时能跑通，不用调参调到死
- 视觉效果够好 —— 粒子颜色来自真实照片，观感就是"这个地方被采样了"
- 配准用 GPS/手动锚点，**视觉上够用**，不追求厘米级
- 全链路可离线，**断网也能演**（我们的看家本领）

### 技术栈

| 层 | 选型 | 备注 |
|---|---|---|
| 前端 3D | React + TypeScript + Vite + **React Three Fiber** | 默认栈，闭眼能写 |
| 粒子渲染 | Three.js `Points` + 自定义 shader | 数十万点级别没问题 |
| 手势识别 | **MediaPipe Hands**（浏览器端） | 零后端、零延迟、断网可用 |
| 深度估计 | 单目深度模型 | ⚠️ 现场确认能否本地跑 |
| 多模态语义 | **阿里千问多模态**（主办方免费提供 + 无限算力） | 顺水推舟 |
| 3D 生成 | ⚠️ **Luxreal**（主办方资源，今天就去问工程师能不能调 API） | 能用上就是白送的加分 |
| 影石侧 | SDK 导出全景素材 / 实时预览 | ⚠️ 待现场确认 |
| 部署 | Vercel + 纯静态离线保底版 | 先把链路打通 |

### 明确不做（防止中途反悔）

- ❌ 用户系统 / 登录 / 注册
- ❌ 后台管理
- ❌ 真·多视角三维重建（SfM/MVS）
- ❌ 物理相框硬件（iPad 模拟已足够，且原案已改为软件手势）
- ❌ 支付 / 商业化功能（讲在 PPT 里，不做进产品）
- ❌ 多景区（**只做 1 个地标做到精**，地图上其他点位是"待补齐"占位）

## 十、还没想清楚的（留给队里讨论，不装懂）

1. **冷启动**：第一个用户看到的是一团几乎没有形状的粒子 —— 这个体验是劝退还是有趣？
   （可以反过来做成卖点："你是第 3 个看见它的人"）
2. **商业化**：原案提了"商业化都有的"但没展开。**PPT 里要讲清一句**，
   我的建议是「地方文旅局采购 + 景区共建」，不是 C 端付费。
