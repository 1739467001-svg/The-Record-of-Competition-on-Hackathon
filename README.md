# 比赛记录库 · The Record of Competition on Hackathon

> 陈俊烨（CJY / HHStudio）的参赛作战室。
> 不是"打完了随手记一笔"的流水账，是一条完整的链路：
> **收到赛题 → 定方向 → 做规划 → 写文档 → 上场 → 复盘 → 把打出来的东西变成下一场的弹药。**

## 为什么要有这个仓库

这半年打了 18+ 场比赛，走完了 `选手 → 志愿者 → 工作人员 → 协办 → 主办` 的全链路。
东西做了一堆、奖也拿了几个，但**散落在 100 多个仓库里，没有被"结算"过**。

所以这个仓库只干一件事：**把每一场比赛，从选题到复盘，完整地沉淀成一份可复用的资产。**
打得越多，弹药库越厚，下一场的起跑线越靠前 —— 这是复利，不是重复劳动。

> 一个比喻：以前每场比赛像**一次性的烟花**，亮完就没了。
> 现在每场比赛要变成**一块砖** —— 打十场，就砌出一面墙。

## 怎么用（你只需要做一件事）

**把比赛链接 / 赛题发给 Claude。** 剩下的按下面这条流水线走：

| 步 | 谁做 | 做什么 | 落在哪 |
|---|---|---|---|
| 1 | Claude | 读懂赛题：赛道、评分标准、时间、交付物、隐性偏好 | 赛事记录草稿 |
| 2 | Claude | 对照 [能力图谱](profile/capability-map.md) 盘弹药，用[选型决策法](playbook/01-选型决策法.md)给 **2–3 个候选方向 + 评分卡** | 同上 |
| 3 | **你** | 拍板选一个（或否掉重来） | — |
| 4 | Claude + 你 | 出项目规划：功能边界、技术选型、时间线、分工 | 同上 |
| 5 | Claude + 你 | 写文档：PRD / README / 路演稿 / 架构图 / 提交包 | 项目仓库 |
| 6 | 你 | **上场打** | — |
| 7 | Claude + 你 | 48 小时内复盘回填，新资产回写弹药库 | 本仓库 |

## 三条底层原则

1. **复用优先。** 每场比赛至少 60% 踩在已有弹药上。从零开始的方向，除非奖励极高，否则不接。
2. **只开一条战线。** 同期只认真打一场。头号盲点是"战线过多、全线漏鱼" —— 这个仓库的作用之一就是**拦住**自己。
3. **打完必须结算。** 没有复盘记录的比赛，等于没打。势能不收口，就永远变不成动能。
